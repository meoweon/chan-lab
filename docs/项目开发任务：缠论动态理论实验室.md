# 项目开发任务：缠论实验室（Chan Lab）

## 一、项目目标

请基于我已经上传的缠论算法代码，为我制作一个完整、可交互、可运行的 HTML 应用。

项目名称：**缠论实验室**

英文名称：Chan Lab

这不是一个普通的缠论指标软件，也不是一个量化交易平台，更不是一个回测系统。

我真正想做的是：

**把缠论这套理论构造成一个理想的、完整的、动态的数学世界，让我能够通过可视化和交互，直观地理解所有结构是如何产生的、彼此有什么关系、有哪些状态、如何转化，以及后续有哪些可能的发展路径。**

可以把它理解成学习几何学时构造一个标准圆形模型。

我们不需要导入真实市场行情，也不需要验证模型能否在真实市场盈利。我们要构造的是一个遵循缠论规则的理想市场，在这个世界中观察缠论结构的完整生命周期。

我希望最终能够：

1. 从最基础的价格运动开始，逐步观察缠论结构如何生成。
2. 理解每个结构的定义、成立条件、构成关系和数学逻辑。
3. 理解不同结构之间的层级关系、包含关系、递归关系。
4. 理解每种结构有哪些状态，以及状态如何转化。
5. 观察当前状态下，理论允许哪些后续发展路径。
6. 能够主动选择某条路径，生成一个新的假想行情，继续观察。
7. 能够从当前结构出发，推演各种条件成立后会发生什么。
8. 最终形成对缠论整体理论体系的直观、完整理解。

核心理念：

**不测而测：不试图预测唯一的未来，而是从当前结构出发，探索所有符合理论规则的后续可能性。**

## 三、产品的核心设计：动态生成，而不是静态展示

我不想要一份普通的缠论知识图谱。

我想要一个可以运行的缠论世界。

### 3.1 理想行情生成器

系统不需要导入真实行情。

请建立一个理想价格运动生成器，可以根据用户选择的结构目标，生成对应的理想K线序列。

例如：

- 一段上涨走势；
- 一段下跌走势；
- 一段盘整走势；
- 一个中枢的形成；
- 一个中枢的延伸；
- 一个中枢的离开；
- 一个中枢的返回；
- 一个中枢的扩展；
- 一段包含背驰的走势；
- 一买、二买、三买等结构形成过程。

生成器的任务不是直接画出最终结构，而是生成价格运动和K线。

随后调用已有缠论算法，对这些K线进行分析。

最终由算法决定实际形成了什么结构。

**生成器负责构造案例，算法负责判定结构，界面负责展示过程。**

如果生成的K线没有形成预期结构，应该调整生成参数并重新验证，而不是强行绘制目标结构。

### 3.2 支持自由生成

用户可以：

- 自由生成一段随机理想行情；
- 指定希望观察的结构；
- 指定上涨、下跌、盘整等初始走势；
- 指定走势长度和波动幅度；
- 指定希望观察的级别；
- 重新生成；
- 保存当前案例；
- 从任意位置重新开始。

所有数据均为系统生成的教学数据。

图层可以单独显示、隐藏、锁定和高亮。

### 4.2 动态生成

支持以下播放模式：

| 播放模式 | 行为 |
|---|---|
| 逐根K线 | 每次增加一根K线 |
| 逐个结构 | 每次推进到下一个结构事件 |

1. 新K线出现。
2. 原有结构如何变化。

4. 是否出现新的分型。
5. 是否形成新的笔。
6. 是否形成新的线段。
7. 是否满足中枢成立条件。
8. 当前走势类型是否发生变化。

不要只在最后一次性显示所有结构。

我希望能够像观察生物生长一样，看到结构一点点形成。

### 4.3 结构确认时间

特别注意：

结构的发生位置、确认位置和实际可知时间不一定相同。

## 六、核心模块三：理论显微镜

每一个结构都应该能够单独打开，进入一个专属的交互式学习页面。

每个结构至少有三个观察模式。

### 6.1 结果模式

展示最终形成的结构。

例如：

- 中枢范围；
- 中枢上下边界；
- 构成中枢的次级别走势；
- 相关结构的关联关系。

### 6.2 生成模式

逐步展示它是如何产生的。

例如：

1. 展示参与构成的K线。
2. 展示包含处理过程。

### 6.3 原理模式

- 正式定义；
- 数学或逻辑表达；
- 必要条件；
- 充分条件（如果有）；

**我要理解结构为什么成立，而不是只记住结构长什么样。**

## 七、核心模块四：状态机与状态转移网络

这是本项目最重要的创新功能。

请不要把缠论仅仅做成一个静态知识树。

缠论中的结构具有生命周期和状态转移关系。

例如一个中枢，可以从形成前的候选状态发展到成立状态，之后出现延伸、离开、返回、扩展等不同演化。

不同状态有不同的前置条件和后续可能性。

### 7.1 每个结构建立独立状态机

请为已实现的结构建立状态模型。

每个状态包含：

- 状态ID；
- 状态名称；
- 状态定义；
- 所属结构；
- 所属级别；
- 进入条件；
- 退出条件；
- 前置状态；
- 后续状态；
- 关联结构；
- 相关定理；
- 对应算法函数；
- 理论依据；
- 规则核验状态。

### 7.2 状态转移网络

请用交互式有向图展示状态之间的关系。

要求：

- 节点代表状态；
- 有向边代表状态转移；
- 点击节点可以查看状态详情；
- 点击边可以查看转移条件；
- 支持展开和折叠；
- 支持缩放和拖动；
- 可以定位当前行情所处的状态；
- 可以显示已经发生的路径；
- 可以显示尚未发生的合法后续路径。

不要把所有状态强行组织成一棵树。

不同路径可能汇合到同一个状态，因此底层应该采用有向图或状态网络。

### 7.3 区分三类状态

- 已经成立：条件已满足。
- 条件待定：尚需后续走势才能判断。
- 不可达：不满足规则，不能进入。

必须把这三种情况清晰区分。

不能把理论上可能的状态误写成当前已经成立的状态。

## 八、核心模块五：未来分支探索——不测而测

我希望能够从任意一个当前结构出发，主动探索后续可能性。

例如：

当前已经形成一个中枢。

系统展示当前状态，以及规则引擎认可的后续候选路径。

用户选择其中一条路径：

- 向上离开；
- 向下离开；
- 继续延伸；
- 离开后返回；
- 满足条件后形成更大级别结构。

以上只是候选教学场景，具体哪些分支可达，必须由实际规则判断。

### 8.1 分支探索交互

用户点击某个分支后：

1. 复制当前行情状态。
2. 保留当前结构和历史。
3. 创建新的假想演化分支。
4. 生成后续理想K线。
5. 重新调用缠论算法。
6. 展示新的结构形成过程。
7. 检查目标状态是否真正成立。
8. 继续展开下一层可能性。

用户可以同时创建多个分支。

例如：

- 世界A：中枢向上离开。
- 世界B：中枢向下离开。
- 世界C：中枢继续延伸。

三个世界独立演化，互不影响。

### 8.2 分支树与状态网络

需要两个视图：

**分支树：** 展示从某个起点出发，用户探索了哪些假想路径。

**状态网络：** 展示缠论理论内部的状态和转移关系。

二者不能混为一谈。

### 8.3 不测而测的核心逻辑

系统不应该直接回答：

「下一步一定会上涨。」

而应该回答：

- 当前已经确定了哪些结构？
- 哪些条件已经成立？
- 哪些条件尚未成立？
- 当前允许哪些后续状态？
- 什么条件会触发某个状态？
- 如果发生某种结构，后续哪些路径会被打开？
- 哪些路径会因此被排除？

即：

当前状态 → 合法转移集合 → 后续状态 → 再次展开。

这是一个条件推演系统，而不是价格预测系统。

### 16.4 当前技术事实（2026-11-06 审视后按主题整理）

**A. 分层与构建**

- 源码分层：`chan-engine.js`（算法逐根回放）/ `chan-generator.js`（价格腿编译 + 场景库；UI 只用其归一化与编译接口）/ `chan-rules.js`（规则注册表，纯数据）/ `chan-state.js`（状态机，纯函数）/ `chan-robust.js`（稳健度评分，纯函数）/ `chan-csv.js`（CSV 解析）/ `chan-microscope.js`（理论显微镜）/ `app.js`（界面与交互）；`index.template.html` 的 8 个占位符经 `build.py` 内联成单文件 `chan-lab.html`。
- C# 原始源码在项目根 `chan/`，共 12 个 .cs 文件；能力对照与各交付清单中的「源码位置」即对应这些类。
- CLI 工具群（16.3E，未接 UI）：`chan-csv / chan-stats / stats-run / smoke-stats / facts-report / structure-census / stylized-facts / smoke-robust`，报告与样例产物统一放在 `docs/`。统计结论属 CLI 侧研究，不混入实验室 UI。
- 引擎数据结构 `stroke / fractal / merged / pivot / divergence / signal / ghost`，字段口径见 `chan-rules.js` 头注与 `chan-engine.js`；无未来函数工程约定 E1：`StableFromBarIndex`、`gRef → gConfirm`、ghost 记录被过滤信号。

**B. 行情来源：路径驱动（已取代场景目标生成）**

- 场景下拉与「生成并分析」按钮均已移除。当前案例 = **种子根 + 用户在流程带一个单位一个单位落实的方向序列 `S.path`**。种子根由归一化参数经一条固定在原点的腿编译出起步K线，再逐帧回放；`buildPath` 按路径顺序折叠：每步复制父前缀、追加一个最小单位（按该步记录的档位构造）、整段重新回放，由回放观察给出该步的结构判定。
- 每个步骤只存单位、方向与标签，不存K线、不存任何结构结论、不预设目标状态。拖滑杆、改种子、改算法参数都会让整条路径重编译并回到最前沿；某步在当前参数下构造失败即如实截断，不伪造行情。
- 只要任一层污染 > 0，路径编译就是**成对**的：同一个根、同一份 v 骨架、同一个分叉点，用 `compileChain` / `appendChain` 分别编译主链与四项污染全为 0 的基线链；腿根数、次级别倍数、长度缩放完全一致，两条链的K线与快照逐根下标对齐。腿只由用户选的下一单位方向（与档位）决定，主链与基线共用同一组 v 位移；两链出现的结构差异因此只可能来自污染，而不是骨架不同。零污染或导入的真实行情没有基线（无对照对象）。
- 生成器仍保留完整场景库与 `generate / analyzeCase`，但 **UI 不再调用**：仅供 CLI 工具与拖动幅度时的 Y 轴探针使用。16.3D 里「教学场景 RN=1 单次 ok=9/19」「free 场景过滤率」等属生成器 / CLI 口径，不是当前 UI 口径。
- 真实行情 CSV 导入：左栏「真实行情」区，支持 Binance 导出或按列格式，有效K线不足 100 根则拒绝导入，默认取最近 1000 根（可配置 150–3000），脏行与无时区时间如实报告；单周期无次级别数据 → 自动关闭并禁用「要求次级别确认」。导入行情可作路径起点，后续步骤仍是按所选单位构造的生成行情；改动生成类参数即离开导入态。

**C. 一个最小单位一步的二叉完全分类（V0.4 的当前形态）**

- 行动空间 `actionable()` 恒为两项：**下一单位向上 / 下一单位向下**，非上即下、互斥且完备，不依赖当前状态、不会无路可走。最小单位三档：**单根K线 / 最小分型 / 最小笔**，默认**最小分型**；选择器是流程带头部的「单位」下拉（`S.gbUnit`，偏好记 `chanlab.gbunit`）。状态机的「合法后续」定向转移与时间算子已一并移除；中枢新生 / 延伸 / 离开 / 移位、背驰、买卖点都不是选项，而是单位序列经算法回放后浮现的判定。
- 单位切换**按步记录、只影响后续**：每个步骤在 `S.path` 里记下自己的 `u`，改下拉框不会回改已落实的历史步骤，历史步骤按各自记录的单位重编译。旧存档步骤没有 `u`，按第三轮的「一笔 = 7 根理想腿」原样回放，已保存案例与旧断言不受影响；新建步骤一律写 `u`。
- 三档都落在缠论层级上：**单根K线** = 1 根 K 线（阳 / 阴）；**最小分型** = 一次已确认的顶 / 底分型（常规 3 根，若分叉点本身已是极值则为 1 根）；**最小笔** = 一条已成立的向上 / 向下笔（常规 7 根，若分叉点本身已是起点分型则为 4 根）。构造器不给结构「打标签」：它只按方向生成候选行情，再由 `E.analyze` 读最后一根分型 / 最后一笔是否**新确认**，未命中就换下一个候选（例如最小分型先试单根回撤，未成再试「推进 + 确认」）。重真实噪声下仍可能造不出结构，此时照常落盘，`formed=false` 如实显示「未形成」，不伪造行情。
- 每步的腿脚本由 `G.buildUnit` 给出，一律 `fixed:true`：`compile` 会把非 fixed 腿强制补到至少 6 根，所以长度缩放 `lenScale` 必须预折进气根数。`lenScale` 只拉伸时间、不改变单位——例如 ×2 时最小分型约 6 根、最小笔约 14 根，判定的仍是「一个分型 / 一笔」。构造器不定向任何目标状态，也不伪造行情。落实统一走 `brApply` 单一入口，流程带虚框与主图幽灵共用它。
- 每步落地后的 `stkVerdict` 是**观察陈述**而非对错判定：先陈述该单位的落地事实（新增几根、分型 / 笔是否确认，未形成就如实说未形成），再对比分叉前后笔数、中枢、背驰、信号，组合出「新笔/延伸 · 中枢新生/延伸/离开/移位 · 背驰 · 信号×N」，标在流程带实心节点上。状态网络退化为纯观察视图，不再承担推演入口。
- 底部「分支流程（完全分类）」：实心节点 = 已走的单位序列（节点文字按该步记录的单位显示「阳/阴」「顶/底」「上笔/下笔」，点选回退并截断到该步），两个虚框 = 下一单位的两个方向（文字随「单位」下拉变化，点选落实）；落实后不切视图，主图与流程带同帧更新。
- 主图「分支预览」图层用与落实时完全相同的 `G.buildUnit` 构造两个方向的幽灵K线（时间轴逐根对齐，根数随单位与 `lenScale` 变化），点击幽灵或流程带虚框即落实该单位，幽灵随即变真实K线。预览为了逐帧跟手只对尾部窗口做 `E.analyze` 判定，落实才跑完整 `E.replay`；两者共用同一个纯构造，同输入逐根一致（`scripts/test-branch-units.js` 覆盖）。
- `BR` 模块现只剩序号生成器 `seq`；**没有多世界树、没有 `BR.worlds`、没有 `chanlab.branches` 持久化**。案例保存（键 `chanlab.cases`）存的是参数、算法参数与路径步骤（导入行情不存路径），加载时重建；按旧架构保存的定向转移步骤在当前构造器下会被如实截断。

## 最后，再强调一次项目的本质

我不是要一个能够告诉我现在该买还是该卖的软件。

我也不是要一个能够分析真实行情的软件。

我要的是：

**一套能够把缠论完整展开的动态理论模型。**

我想亲眼看到：

- 一根根K线如何形成分型；
- 分型如何形成笔；
- 笔如何形成线段；
- 次级别走势如何形成中枢；
- 中枢如何延伸、离开、返回和扩展；
- 走势如何形成上涨、下跌和盘整；
- 不同级别如何递归嵌套；
- 背驰如何形成；
- 买卖点如何从前置结构中产生；
- 一个状态如何转化为另一个状态；
- 当前结构如何约束未来的可能发展。

我希望能够像探索一个数学世界一样，在里面自由移动、观察、拆解、构造和推演。

**请不要把它做成缠论知识展示网站。请把它做成一个可以运行的缠论理想世界。**
