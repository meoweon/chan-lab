# lab ⇄ mdk 缠论实现差分校验

lab 的缠论引擎（`src/chan-engine.js`）与 mdk（`reference/mdk`）的 C# 实现**不是靠人眼对齐的**：
本目录把 mdk 自己的代码编译成探针，同一批 K 线两边各跑一遍，逐字段比对。

```bash
node scripts/align/run.cjs          # 120 例分析 + 3 例逐根回放
node scripts/align/run.cjs 300      # 例数
node scripts/align/run.cjs 60 --no-build
```

退出码 0 = 全等。依赖 .NET 10 SDK（首次会 `dotnet build` 探针，约 20s）。

## 比对什么

| 模式 | mdk 侧 | lab 侧 | 字段 |
|---|---|---|---|
| analyze | `ChanAnalyzer.Analyze` | `E.analyze` | 分型（合并序号/原序号/价/顶底/确认根）、笔（端点/价/方向/是否确认/稳定根）、中枢（ZG/ZD/笔区间/笔数/是否确认/离开笔）、买卖点（类型/方向/时间/价/参考价/参考根/止损/面积比） |
| replay | `ChanBackfill.ReplayPoints`（700 根滑窗，逐根） | `E.replay` | 每帧「记账时间 == 当根」的信号集合 |

价格用相对容差 1e-6 比较。analyze 覆盖 9 组参数变体（暖机 0/10/30、面积比 0.5/0.9/1.2、`maxPoints`、关掉次级别确认、确认窗口 5/30/120）与短序列 / 平坦 / 大跳空等边界。

## 当前结论（2025-11 基线）

- analyze：120 例，分型 11620 / 笔 2644 / 中枢 629 / 买卖点 321，**0 处不一致**。
- replay：3 条 900+ 根序列（带次级别），信号 7 / 18 / 32 个，**逐个相同**。

## 唯一保留的差异：回放窗口的预热（工程约定 E2）

mdk 的 `ReplayPoints` 写死 `if (i + 1 < windowBars) continue;`（`windowBars = max(120, AnalysisBars)`，默认 700），
历史不足 700 根时不出任何结论；lab 的案例多在几十~几百根，所以从案例起点用**扩展窗口**
（`窗口 = [max(0, i+1-700), i]`）逐帧复算——等价于「mdk 在线、历史还在积累」时的口径。

因此：**序列长度 ≥ 700 根时两者逐字段相同**；不足 700 根的早期帧，lab 会给出「窗口尚短」的结论，
mdk 回填则保持沉默。这一条写在引擎头注释 `E2` 和界面「无未来函数」说明里，不是隐藏偏差。

## 另一个发现：mdk 会重复发同一结构

锚定笔的 `StableFromBarIndex` 会随 `pts[ssi+3]` 被替换而后移，`ReplayPoints` 没有跨帧去重，
于是同一结构会在新稳定根上**再发一次**（记账价随当根收盘微调）。实例：`3卖 gRef=726` 在 746/747 各发一次
（38.376 / 38.946）；`1买 gRef=705` 在 713–722 连发 5 次。

lab 曾经用 `seenSig` 去重，导致回放信号比 mdk **少**（7/18/32 → 5/9/…）；现已按对齐原则删除去重，
改在绘制层去重（`uniqueSig`），所以图上不会叠两个标签，而数据与 mdk 逐条一致。

若上游认为重复发信号是缺陷，应改 mdk 的 `ReplayPoints`；lab 跟随即可。
